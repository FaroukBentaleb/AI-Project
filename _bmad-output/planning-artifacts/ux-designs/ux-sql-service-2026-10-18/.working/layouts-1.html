DevAssist Hub · SQL module — layout directions (round 1)

Grayscale, low-fidelity wireframes. They show structure, density and navigation only. Colour, type and the dark theme come later. Each direction is shown on the Library and Generate screens. The module runs on its own inside a plain router-outlet, so each layout carries its own small header: the module name, module navigation and the sami ▾ identity chip.

1 · "GitHub list"

A single wide column of query cards with module tabs along the top, like a GitHub issues list. Each card shows its SQL inline, which directly meets "SQL visible without extra clicks". People scanning by title, description and badges get plenty of room to read.

Trade-off: the inline SQL makes cards tall, so only about 3–4 queries fit per screen. Expect paging and scrolling. Generate is a simple top-to-bottom form, so the result sits below the prompt and needs a scroll on smaller screens.

FROM orders o JOIN regions r ON r.id = o.region_id

SELECT c.id, c.name, SUM(o.total) AS revenue
FROM customers c JOIN orders o ON o.customer_id = c.id

2 · "Supabase split"

A sidebar stays on the left with the module nav and a searchable list of saved queries by title. The main pane shows whichever query is selected, or the generator, like an SQL-editor workspace. Moving between queries takes one click and keeps your place, and the Generate split puts the prompt and its output side by side.

Trade-off: the sidebar only shows titles, so you have to select a query to see its SQL. That breaks "SQL visible without extra clicks" for browsing, but suits people who already know what they want. Filters have to be squeezed into the sidebar, and the main pane is narrower.

3 · "Dense table"

Top tabs and a compact table with one row per query: title, tags, author, badges, last used and a copy icon. A preview panel on the right shows the selected query's full SQL, and a row can also expand in place. This packs about 15 queries above the fold and makes sorting and comparison easy. It suits a library that grows past a few dozen entries.

Trade-off: with no selection, the SQL is one click away (select or expand a row). That's a partial fit for "SQL visible without extra clicks", which a preview that follows hover or the keyboard could ease. Descriptions get cut short. Generate puts the result behind tabs, so warnings and examples are easy to miss unless the tab labels show counts.
