# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

DevAssist Hub: an ESPRIT university project (course "IA for Software Engineering"). A multi-module monorepo of independent Spring Boot 3.3.5 / Java 21 microservices, an Angular 18 frontend, and shared infrastructure. Each module is a CRUD feature plus one Hugging Face Inference API LLM feature. sql-service (NL→SQL with Groq + Jina/Qdrant RAG), commit-service (ZIP → diff → commit message) and snippet-service (function → docstring) are implemented; bug and review services are still scaffolds (`package-info.java` placeholders). Details in `README.md` and `docs/PROJECT_CONTEXT.md`.

## Commands

There is no root build; each service is a standalone Maven project (no Maven wrapper committed) with its own `pom.xml` and `Dockerfile`.

- Full stack: `copy .env.example .env` (set `HF_API_TOKEN`), then `docker compose up --build`
- Only your service plus shared infra: `docker compose up --build eureka-server postgres api-gateway <service>` (commit-service also needs `commit-model`; sql-service needs `qdrant`)
- Single service, outside Docker: `mvn spring-boot:run` or `mvn test` inside the service directory. Local JDK may be 8 and Maven absent; the services need JDK 21, so run Maven in a container, e.g. `docker run --rm -v "$PWD:/app" -v m2:/root/.m2 -w /app maven:3.9.9-eclipse-temurin-21 mvn -B test` (use `MSYS_NO_PATHCONV=1` and `$(pwd -W)` from Git Bash on Windows). Run a single test with `mvn test -Dtest=ClassName#method`. `application.yml` requires `SPRING_DATASOURCE_*` env vars (no defaults), so the Postgres from compose must be reachable.
- Frontend (in `frontend/`): `npm install`, `npm start` (`ng serve`, :4200), `npm run build`, `npm test` (`ng test`, Karma/Jasmine). No lint script is configured.
- sql-service CI (`.github/workflows/sql-service-ci.yml`, the only workflow): `mvn -B -ntp verify` in `sql-service/` runs surefire unit tests plus Testcontainers `*IT` integration tests (needs Docker), then a Docker image smoke test against `/actuator/health`.
- sql-service E2E (needs the stack up): `docker compose -f docker-compose.yml -f docker-compose.e2e.yml up -d --build`, then `node scripts/e2e/uj1-e2e.mjs` or `node scripts/e2e/uj3-rag-lift.mjs` (`E2E_MODE=real` to hit the real provider). The e2e override swaps the LLM for `scripts/e2e/llm-stub`; `docker-compose.planb.yml` is the demo fallback (longer timeouts, alternate model). See `docs/sql-service-e2e.md` and `docs/sql-service-demo-runbook.md`.

Ports: frontend 4200, gateway 8080, commit-model 8000, Eureka 8761, commit/snippet/bug/sql/review services 8081–8085, Postgres 5432, Qdrant 6333 (REST) / 6334 (gRPC).

## Architecture

- **Routing:** the Angular app calls the gateway only. `api-gateway/src/main/resources/application.yml` maps `/api/{commits,snippets,bugs,sql,reviews}/**` to `lb://<service-name>` via Eureka, so a route works only if the service's `spring.application.name` matches the route's `lb://` name. CORS is configured in the gateway (`FRONTEND_ORIGIN`).
- **Database per service:** one Postgres instance with five databases (`commit_db`, `snippet_db`, `bug_db`, `sql_db`, `review_db`), each with its own user, created by `infrastructure/postgres/00-create-users.sh` and `init.sql`. Services use `spring.jpa.hibernate.ddl-auto: validate`, so tables never come from Hibernate. commit-service and sql-service own their schema with Flyway (`src/main/resources/db/migration/V*__*.sql`; add a new `V<n>` file, never edit an applied one); the scaffold services have no migrations yet.
- **Config:** everything is env-driven through `.env` → `docker-compose.yml` → each service's `application.yml` (`${VAR:default}` placeholders). Shared variables: `HF_API_TOKEN`, `HF_MODEL`, `EUREKA_CLIENT_SERVICEURL_DEFAULTZONE`. Tunables in the `hf:` block: `HF_TIMEOUT`, `HF_RETRY_MAX_ATTEMPTS`.
- **Service layout:** every service uses packages `controller`, `service`, `repository`, `dto`, `entity`, `exception` under `com.devassisthub.<name>`. Each has a `GlobalExceptionHandler` (consistent JSON errors), actuator health, springdoc OpenAPI at `/swagger-ui.html`, and Eureka registration.
- **commit-service flow:** the user uploads a ZIP plus a project name (`POST /api/commits/uploads`, multipart). `ZipSnapshotReader` turns it into a `{path: text}` snapshot (text files only; ignores `.git`, `node_modules`, `target`, binaries; strips a single shared top-level folder; enforces `commit.upload.*` limits). `CommitUploadService` diffs it (`DiffBuilder`, unified diff, java-diff-utils) against the project's previous upload's stored snapshot (the first upload diffs against nothing, so the whole project is the diff; an identical upload is `409 NO_CHANGES`). `DiffTrimmer` cuts the diff to `commit.model.max-diff-*` (the model has a short context), then `ModelClient` calls the FastAPI model service. Tables: `project`, `commit_upload` (snapshot + diff + message), created by Flyway `V1`. Projects match case-insensitively. The model call runs outside any DB transaction, and the project row is created only after the model answers.
- **Model service contract:** `POST {COMMIT_MODEL_URL}/generate {"diff": "..."}` → `{"message": "..."}`. `commit-service/ai/` (compose service `commit-model`, port 8000) serves a LoRA fine-tune of Qwen2.5-0.5B-Instruct trained on CommitPackFT to write Conventional Commits subjects; with no adapter in `ai/model/adapter/` it answers with a rule-based fallback (`GET /health` shows `mode: model|stub`). Training happens on Kaggle via `ai/training/commit_model_kaggle.ipynb` (generated by `ai/training/make_notebook.py` from `train_commit_model.py`, inlining `commit_prompt.py` + `commit_data.py`); see `ai/README.md`. `ai/commit_prompt.py` is the single source of truth for the prompt/trimming shared by training and serving: change it only together with `PROMPT_VERSION` and a retrain. Real-model mode needs `COMMIT_MODEL_REAL=1` in `.env` (build arg that installs CPU torch). `ModelClient` must stay on HTTP/1.1: the JDK client's default h2c upgrade makes uvicorn drop the POST body (422).
- **Frontend (commits):** `frontend/src/app/features/commits/` is a standalone page (`commits-page.component.*`) with a drag-and-drop zone (`drop-zone.component.ts`, plus a page-wide drop overlay), a GitHub-style diff viewer (`diff-viewer.component.ts`, `diff-parser.ts`) and `commit-format.ts` helpers. It deliberately avoids `@angular/forms` (not a project dependency). Run its specs with `CHROME_BIN=<edge/chrome> npx ng test --watch=false --browsers=ChromeHeadlessCI --include='src/app/features/commits/**/*.spec.ts'`.
- **snippet-service:** mirrors commit-service. CRUD on `snippet` (Flyway `V1`): `POST/GET /api/snippets`, `GET/PUT/DELETE /api/snippets/{id}`, `POST /api/snippets/{id}/docstring` (regenerate); create with `"generate": true` saves the snippet and its model docstring in one call, and a model failure saves nothing. `ModelClient` (HTTP/1.1, timeout + retry, validated reply) calls `snippet-service/ai/` (compose `snippet-model`, host port 8001): `POST /generate {"code","language"}` → `{"docstring"}`; language is `python|java|javascript`. The model returns plain docstring text; the Angular page wraps it in the language's comment syntax (`snippet-format.ts`, mirrors `format_docstring` in `ai/snippet_prompt.py`). Same train/serve rule as commits: `snippet_prompt.py` is shared, bump `PROMPT_VERSION` and retrain on change; `CodeTrimmer` and `MAX_CODE_CHARS` (2500) must match. Fine-tuning: Qwen2.5-Coder-0.5B-Instruct + LoRA on CodeSearchNet via `ai/training/snippet_model_kaggle.ipynb`; see `ai/README.md`. The model service has no fallback: it loads `ai/model/adapter/` (git-ignored; unzip `snippet_adapter.zip` there) at startup and exits if it is missing; `SNIPPET_DTYPE=bfloat16` cuts its RAM use. `docker-compose.snippet-test.yml` runs only eureka, postgres, gateway, snippet-model and snippet-service with remapped host ports (5433, 8090) for small machines.
- **sql-service:** differs from the other services (own `llm/`, `rag/`, `validation/`, `seed/` packages; JSON is snake_case). Flow in `GenerationService`: `ExampleRetriever` pulls similar saved queries from Qdrant (collection `sql_embeddings`, embeddings via Jina, 384 dims) as few-shot examples → `LlmClient` (Groq OpenAI-compatible chat, `GROQ_API_KEY`; `hf.*` settings still exist for the HF path) → `SqlExtractor`/`RefusalDetector` → `ReadOnlyValidator` (parses, never executes; only a single SELECT passes). One LLM attempt, hard deadline `sql.generation.deadline` (13s) kept under the gateway's route timeout. Prompts are versioned under `src/main/resources/prompts/<SQL_PROMPT_VERSION>/`. `Reconciler`/`QueryIndexer` keep Qdrant in sync with Postgres rows; `SeedCorpusSeeder` loads `seed/seed-queries.json` idempotently. Spring profiles `demo` and `planb` (`application-demo.yml`, `application-planb.yml`). Local runs read secrets from the git-ignored `sql-service/.env.local`; `GROQ_API_KEY` and `JINA_API_KEY` are required for real generation and are not in `.env.example`.
- **Qdrant/RAG:** commit-service no longer uses Qdrant or Hugging Face (sql-service still does, so compose keeps the `qdrant` service).
- **Frontend:** `frontend/src/app/app.routes.ts` lazy-loads one NgModule per service (`loadChildren` → `*Module`) under `src/app/features/{commits,snippets,bugs,sql,reviews}`, each with its own `*.routes.ts`; the default route redirects to `commits`. `shared/api.service.ts` is the common HTTP wrapper and `environments/environment.ts` sets `apiBaseUrl` to `http://localhost:8080/api` (the gateway).

## Conventions and rules

- Ownership: one teammate owns one service folder and its Angular feature module. Don't edit another member's service. Shared files (`docker-compose.yml`, gateway routes, Postgres init scripts) change only via a reviewed PR. Check `git branch --show-current` to see which module you are on (`commit-service` is Farouk's).
- Branches: `feature/<service>-<topic>`; PRs target `develop`; `main` only at milestones. Conventional Commits, e.g. `feat(commits): add commit message request`.
- LLM rules (every module): use a dedicated HF client class with strict timeout and retry; give clear errors for quota exhaustion and a missing key; validate and parse model output before returning it; never send raw personal data to the model; keep prompts in a `prompts/` resource folder (not in controllers), versioned and documented.
- Definition of done: CRUD, LLM feature, validated model output, clear error handling, passing service-layer tests, Angular feature wired through the gateway, documented prompt.
- Never commit `.env` or secrets (`.env.example` is the template).
